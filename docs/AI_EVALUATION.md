# Uniissuehub AI evaluation

Generated by `npm run eval:ai` (backend). Do not edit by hand.

## What this measures

- 192 labelled campus complaints in `backend/eval/ai_eval_set.psv` (synthetic, written in the style of hostel complaints, including negation, Hinglish and non-complaints; no real student data). Labels follow the rubric below.
- Split: 128 dev rows and 64 held-out rows (every third row). Thresholds and rules were adjusted only while looking at dev rows. The harness printed held-out totals too, so they are a sanity check on the dev work, not a blind test. The baseline column does not depend on any tuning.
- **Baseline** = the original engine alone (`aiService.js`). **With safety net** = `aiAssessment.js` (confidence, safety rules, only-raise priority).
- The submit form does not send a priority, so the final priority comes only from the AI and the safety rules (modelled as a student priority of Low, the floor). If a student does pick a priority, the AI can only raise it.
- The labels were written by one person (the developer), so they are a reasonable reference but not ground truth. Treat the numbers as a regression benchmark, not as a claim about accuracy on real traffic.

Rubric: **Critical** = immediate danger to people (fire, shock, gas, flooding, injury, collapse). **High** = essential service out for long, theft/harassment, health risk, exam impact. **Medium** = ordinary fault. **Low** = cosmetic or suggestion.
Sentiment: **Urgent** = danger or time-critical. **Frustrated** = explicit dissatisfaction or repeated unresolved problem. **Polite** = courteous request or thanks. **Neutral** = plain factual report.

## Known limits

- Small synthetic set written by the developer; real complaints will be messier.
- Keyword engines miss paraphrases. The confidence values are heuristics, not calibrated probabilities.
- Category is advisory only: the student chooses it. Priority is the only AI output that changes routing, and it can only go up.
